# 智能戒指与音箱联动交接

## 文件

| 文件 | 用途 |
| --- | --- |
| 戒指音箱联动测试.html | 页面与 JavaScript 源码。手势、报警语音、天气查询、测量界面都在这里。 |
| RingBridge.cs | Windows 蓝牙测量桥接源码。读取戒指的自定义 BLE 服务，并在本机提供网页和测量接口。 |
| build.cmd | 修改 C# 后重新编译桥接程序。只修改 HTML 时，保存并刷新浏览器即可。 |

## 在 Windows 调试完整演示

1. 在 Windows「设置 → 蓝牙和设备」配对戒指。确认在记事本里双击触控区能换行。平板上的 nRF Connect 如果还连着戒指，先断开。
2. 先运行 build.cmd 生成 RingBridge.exe，再双击运行 RingBridge.exe，保留控制台窗口。在 Edge 地址栏打开 http://127.0.0.1:8765/ 。这里使用 Windows 已配对的设备读取测量数据，无需使用浏览器的蓝牙选择器。
3. 如果音箱支持作为 Windows 音频输出，在「设置 → 系统 → 声音 → 输出」选择它。先点页面的「开始测试」，再点击页面空白处，让页面接收戒指的按键。
4. 输入城市。双击戒指触控区会查询并播报当前天气，也可以点「播报天气」测试。天气请求依赖联网和 Open-Meteo。
5. 4 秒内做两次向下手势，播放「我摔倒了」。向上动作不清零。这个演示由手势触发，和摄像头的跌倒判定尚未接通。
6. 戴好戒指，点「开始测量」，手保持静止约 30 秒。页面显示心率、血氧、戒指测得温度。

### 分开检查

- 普通键盘也能调试页面。进入测试状态后，按 Enter 模拟触摸双击，按两次 Page Down 模拟两次向下动作。
- 直接打开本地 HTML 可以先调试手势、语音和天气。直接打开时，网页的蓝牙选择器和 Windows 键盘配对可能出现已连接但扫描不到戒指的情况。完整联调优先使用上面的本机地址。
- 桥接源码默认识别本组戒指 BCL6039F5A。如果另一枚戒指名称不同，修改 RingBridge.cs 中的 Ring 常量并运行 build.cmd，再运行新生成的 RingBridge.exe。该戒指的固件还需要支持同样的协议。
- build.cmd 使用 Windows 自带的 .NET Framework C# 编译器。重新编译需要 Windows 10/11 SDK 的 UnionMetadata 和 .NET Framework 4.8 Developer Pack。编译前关闭正在运行的桥接程序。
- 如果页面打不开，先看桥接窗口有无启动提示。页面能打开但测量失败时，保留页面的错误原文。提交代码时可以把 EXE 当作调试产物，HTML、C# 和编译脚本是可继续修改的工程文件。

## 摄像识别从哪里接入

- 网页的按键入口是 HTML 中的 window.addEventListener('keydown', …)。报警语音在 PageDown 计数达到 2 的分支。若摄像识别也会产生求救事件，可先把这一段语音触发提取成一个函数，再由手势事件和摄像识别事件共同调用，并做重复触发控制。
- 天气入口是 HTML 中的 reportWeather()。目前由双击和「播报天气」按钮触发。
- 生理测量在 RingBridge.cs 的 Measure() 中。桥接运行在本机 127.0.0.1:8765，网页通过同源 POST /measure 取得 heart、oxygen、temperature，字段可能为空。它没有对外开放接口。如果摄像识别运行在音箱进程或其他设备，请根据组内已有接口接入事件，再决定由页面还是音箱端负责播报。
- 摄像识别代码由音箱组接入。本包没有引入摄像代码或外部推送配置。

## 已验证范围

实物已分别验证过 Windows 能收到戒指按键、网页蓝牙能读到三项指标，以及 Windows 在保留配对时能发现测量服务。当前原生桥接版已经编译并启动过，网页与真实戒指同时运行的链路还需要在常规 Windows 会话里联调。包中使用的是演示警报逻辑。
